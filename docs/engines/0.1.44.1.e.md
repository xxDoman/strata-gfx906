## What it fixes / what it adds

The engine has **two paths**: the packed path (`qwen4exp`) and a native one for `qwen35moe` models
(`q36`). The configurator used to write flags into the config that the selected path does not read — the
engine then answered with its own log line and ignored them:

```
strata-q36: ignoring --kv q4_0 (not an option of this engine)
strata-q36: ignoring --mmap-experts (not an option of this engine)
strata-q36: ignoring --vram-reserve-mib 1024 (not an option of this engine)
```

The user thought they were steering the KV cache and the VRAM reserve. What changed:

- **One list in one place**: `PATH_OPTIONS` — `q36` = **25 flags** taken from
  `src/qwen35/q36_engine.cu:2400-2427`, packed = **175 literals** from `src/program/generate.cpp`,
  with the date they were checked.
- A `q36` config goes out **without** `--kv`, `--mmap-experts`, `--vram-reserve-mib[-later]` and with
  `--expert-vram` instead; card branches go through `path_set_arg` (no blind index).
- A **final gate** refuses (`ModelNotRunnable`) a `q36` config that still carries a flag outside the
  table; the UI dims such a field with the reason and prints the full list.
- A **warning built from the engine's own log** (the `ignoring …` lines of the last start), so the list
  cannot go stale, and a **diagnostic of the existing config** (list of unsupported flags + removal only
  after a click, `POST /api/config/clean`, with a `.bak` copy).

## How it was proven

- **Probe without a GPU** (`probe-konfigurator-opcje.py`, A/B old vs new): `pack/single`,
  `pack/layer_split`, `pack/helper` = **0 differences in the whole JSON** (the packed path is untouched),
  while `q36` loses the three flags, gains `--expert-vram`, `path_unsupported()` = `[]`,
  `ignored_options()` on the **production** log = 3 lines, and `config_path_diag()` on the real config =
  4 flags, **file untouched**; `config_clean` removed 4 flags and made a `.bak` copy.
- `docker build -f Dockerfile.144-1e`: all `RUN` controls — 67 `&& grep -q` anchors (63 in the launcher
  block, 3 of them negative) and the launcher's md5 in the image equals the file on disk.
- **Smoke from the image** (separate container `strata-0441e-smoke`, port 8199, **no `--autostart`** so
  no card was used, `/models` and `/data` mounted `:ro`, `/work` = copies of the real config and log):
  `/api/data` gave `diag.path=q36`, `paths` = 25 flags for `q36` / 175 for the packed path,
  `/api/models/infos` = 14 models with `sec_counts {1:4, 2:0, 3:2, 4:8}`, `POST /api/start` on a `bad`
  model → `blocked: true` with the verdict's reason and zero `unknown argument`; the config copy was
  bit-for-bit unchanged after the whole smoke.
- **Production, read-only (`GET`)**: the real container ran this exact image (`docker inspect strata` →
  `sha256:a4e0c060ff62…`) and the real config still carried the old flags — the panel showed both the
  point-by-point diagnostic and the warning from the engine's own log.

## What is NOT proven

- **The engine-level gate on a live card** — no engine run was allowed (cards forbidden). "The `q36`
  path really does not receive `--kv`" is proven **statically** (argv built from the config + A/B) and
  **by the engine's own words** (`ignoring …` lines about the old config); no run of the *new* config on
  a live card.
- **`--expert-vram -1`** is the engine's default read from source (`q36_engine.cu:2389`, `:2476`); no run
  with an explicit GiB number was measured.
- **Completeness of the packed list** (175 literals): whether a flag takes a value was resolved only for
  flags the launcher exposes, the rest default to "valued" — which is exactly why the packed path is
  **logged, not blocked**.
- **The UI in a browser**: verification is a render (HTML/JS + `node --check`), not clicking in a browser;
  there is no screenshot (the session had no GUI).
- The tag was never published.
