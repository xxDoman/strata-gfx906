## Two numbers, not one

Release `0.2.9`, engine **0.1.55** (0.2.3 shipped 0.1.48). The tag carries the release number — the number on
upstream's release page — while `/opt/strata/RELEASE` says `release=0.2.9 / engine=0.1.55`, and that is what
the benchmark report reads.

**`0.2.8` was skipped on purpose.** It was published on 2026-10-29 with engines from `8c1aea4b`; `0.2.9`
supersedes it two days later and carries its fixes, so building both would have produced an image nobody
would ever pull.

## What upstream changed, in the parts that touch this image

The 0.2.8/0.2.9 notes name faster prompts on Strix Halo under Windows, parallel requests on NVIDIA
(1.45× at eight concurrent), Gated DeltaNet prompt kernels on NVIDIA tensor cores, Intel Arc B-series, new
DeepSeek GGUF layouts, Unsloth 1-bit sets, and a chunked prefill kernel for RDNA **gfx12** from 64 tokens.
**gfx906 is not named anywhere in them.** That is the whole honest summary: this tag is a newer application
layer and newer upstream plumbing, not a faster card.

## What we had to re-base, because upstream moved under our patches

Two hunks of the E-set did not apply any more, and neither was a cosmetic conflict:

| our id | what changed in 0.1.55 | what we did |
|---|---|---|
| **E4** — `X(12)` = Q4_K in `STRATA_D_FMTS` | upstream added `X(147) X(148) X(149)` to the `D` family list, and `12` is **still** only in `GU` and `MMVQ` | inserted by hand in both branches, exactly as in 0.2.3 |
| **E1** — attention-score buffers sized from the model geometry, 512-row warmup | #4708 rewrote the warmup line to `min(tmax, ctx)` and added a `reset()` after the first probe | re-based to `max(1, min(min(tmax, ctx), 512))` — upstream still picks a **2048** default chunk when 512 does not fit, and warming a whole chunk allocates the whole scores buffer |

Everything else applied with offsets: the CMake blocks (rocBLAS reader wired into `STRATA_HIP_GFX906`, the
cuBLAS shims), the `gguf_reader` upload path for Q4_K/Q6_K, optional `nextn_predict_layers`, the stream-priority
names DFlash2 needs, and the removal of the gate that keeps qwen35/36 out of a gfx906 build.

## Two findings that are not regressions — and one that is upstream's

- **The ISA guard flagged two functions upstream never listed.** `iq512x_rows` and `iq512_reference_gu_rows`
  are AVX-512 code added in 0.2.5 and missing from `WIDE_PUBLIC` in `tools/check_isa_guard.py`. Both are
  reached only behind `cpu_avx512_ok()` (`native_expert.cpp:456`, and `g_iq512` in `ds4_gg_cpu.cpp`), so a
  Haswell never executes them. The **0.1.52 binary carries the same two findings**, which is the proof that
  this is bookkeeping, not a trap introduced by 0.1.55. We added the two names to our copy of the guard with
  the reason in the comment; the portable probe under `qemu -cpu Haswell` and the `vpdpbusd` scan are the
  evidence that nothing was silenced.
- **`0.2.7`'s engine sum was never entered in the release record** (`FLAVORY_SILNIKA` in `policz-wydania.py`),
  so the gate would have scored that image as a `native` build. Fixed for both 0.1.52 and 0.1.55.

## How it was proven

- **Release gate passed**: the image boots and answers (`/` → HTTP 200), `check_isa_guard` reports 0
  violations, `ggml_vec_dot_q8_0_q8_0` holds 0 `vpdpbusd`, the `qemu -cpu Haswell` probe runs without SIGILL
  and returns the native result, the model scan over the real directories lists 25 models with no traceback
  in the log, and every published tag matches the release record.
- **A/B against 0.1.52** (0.2.7's engine): one MI50, 80 W, same model, same flags, same sidecars, four arms
  interleaved old/new/new/old. **Parity within run-to-run spread.** The spread is wider than the difference
  between the two engines, so **no throughput numbers are published for this tag** — quoting them would be
  quoting noise.

## What is not proven

- **The pack was never loaded on the GPU under the gate.** Gate point (d) — a real pack loading and one
  generated token on the MI50 — was not run: the first start on the card belongs to the operator. Every claim
  above is about the image and the binary, not about a running workload.
- **Speed.** See above: parity, no numbers.
- **DFlash2 on gfx906** is still dead — measured on 0.1.48 as 0 of 126 drafts accepted, and nothing in
  0.1.55's notes touches that path. It compiles; it does not draft.
