## What it fixes / what it adds

A launcher-only change with a deliberate refusal built in:

- **The "insert the missing key" path now refuses** with the reason
  `[brak miejsca w nagłówku - nie poświęcamy kluczy]` (`_MI_REFUSE_NO_ROOM`, `_MI_REFUSE_NO_ROOM_ID`)
  instead of overwriting a key that was already in the header. Repairing metadata must not cost the
  model a different key.
- **Every write to a model file goes through a hard gate** (`_MI_WRITE_KINDS` + `_mi_hard_gate`): the only
  permitted operation is replacing the **value of an existing key in place**. After a write the file must
  (a) have a superset of the keys, (b) have the same tensor directory (offset + content), (c) have the
  same size — otherwise the backup is restored and the UI shows a failed step.
- Repairing `attention.compress_ratios` stays available (that is the legitimate case).

## How it was proven

- **Offline test without a GPU** (`models-infos-tests/test_1441d.py`): **36 assertions OK / 0
  discrepancies** — R1 the plan refuses for two files, R2 zero writes and zero copies, C1
  `compress_ratios` 40 → 4 works, G1 the three gate conditions, G2 sabotage → `ok=False` **and the file
  restored bit-for-bit**.
- `docker build -f Dockerfile.144-1d` passed every `RUN` control (`_MI_DONORS = ()` as a *positive*
  assertion ×1, `_mi_hard_gate` ×2, `engine build 0.1.44.1.d`).
- **A/B old vs new verdicts**: zero differences in the verdict columns; the only change is the text of
  `rep.reason` / `rep.kind` (intended).
- **Header identity, byte for byte**: the first 12,038,624 B of the model file hash to
  `3c5ebdf458da0a44…`, identical to the sha256 of the `.hdrbak` sidecar that was removed externally — the
  header in the file *is* that one.
- A/B on a copy with llama.cpp (`-ngl 0`, CPU/mmap, no GPU used): healthy vs damaged header, in
  `klucze-1441d/llama-{zdrowe,zepsute}.log`.
- `bash -n llama-run.py` clean, plus the console message for a closed process (`key not found in model`)
  demonstrated on the real `~/server.log`.

## What is NOT proven

- **The literal B.2 step from `.hdrbak` can no longer be executed** — the file was deleted externally at
  17:27:33. It was replaced by the byte-identity proof above, which is weaker in form but exact in
  content.
- **The Strata engine's own gate on the repaired file** — the round was forbidden from using the cards,
  so this link in the chain stays open (same `R9` as in `.1.b`).
- **Who restored the header, and why** — only the effect is visible (mtime 17:27:33, sidecar gone,
  sha `0abe6608…`, external `docker events`). An automatic process cannot be excluded.
- **That the gate cannot be bypassed by a future new `kind`** — there is a single whitelist
  (`_MI_WRITE_KINDS`); adding a new write kind takes a deliberate edit and breaks the CFG-7 test.
- **`serve.*` behaviour of this image on a live model** — no container was raised from `.1.d` (the
  production container was left untouched and kept the card).
- The tag was never published.
