## Two numbers, not one

Strata has a **release** number and an **engine** number. This release is `0.2.1`; the engine inside is
`0.1.46` (upstream's own packages are named `strata-engine-0.1.46-*`, and `project(strata VERSION 0.1.46)`
sits in the `v0.2.1` tag). The image is tagged with the release — the number a reader sees on the upstream
release page — and carries `release=0.2.1 / engine=0.1.46` in `/opt/strata/RELEASE`, which is what the
benchmark report reads.

## What upstream fixed for gfx906 in 0.2.1

Issue [#3172](https://github.com/Niko1221/Strata/issues/3172) listed three blockers. All three went in, and
the maintainer said so in the thread: the Qwen3.6 engine is no longer built for gfx906, the W4A4 target
gets `GGML_USE_HIP`, and the trellis overlay plus `moe_f16_kq` are in the HIP source list. The gfx906 dp4a
path (`__dp4a` → `v_dot4_i32_i8`) has been in `platform/hip_compat/strata_hip.h` since the gfx906 port.

Consequence: `git diff v0.2.1` is empty on this tree and the build needs no patch. The trellis overlay now
configures and links (on 0.2.0-beta it had to be turned off with `-DSTRATA_MMQ_TQ_OVERLAY=OFF`).

## What we add on top

| id | what | why it is needed here |
|---|---|---|
| **E5b** | rocBLAS solution-table reader wired for gfx906 — `find_package(rocblas CONFIG QUIET)` in the `STRATA_HIP_GFX906` block and `(STRATA_ENABLE_HIP OR STRATA_HIP_GFX906)` on the target | the reader is upstream, but its gate sits on `STRATA_ENABLE_HIP` while gfx906 takes the `HIP_GFX906` branch, so without the wiring it compiles to nothing |
| — | the **gfx906 rocBLAS table** (108 rows, tuned 2026-10-10 on MI50, rocBLAS `5.2.0.dabb6df2b9`) at `/opt/strata/rocblas-tuning.txt`, plus `STRATA_HIP_PROMPT_F16=1` | the table is measured on the FP16-in/out prompt path, so that switch ships in the image |
| **E1–E4, E5c, E7** | the qwen35/36 engine restored for gfx906: `q36_engine.cu` from the 0.1.45 line (attention buffers from geometry, `ident`/`rinv` slack, `upload_f32` accepts Q4_K/Q6_K), `X(12)` = Q4_K in `STRATA_D_FMTS`, the `cublasSgemm`/`cublasGemmStridedBatchedEx` shims, `nextn_predict_layers` optional | upstream keeps this engine out of the gfx906 build, so the image would otherwise run only `qwen4exp`; a Qwen3.6 file without an MTP block is a valid file and must load |
| — | `serve/`, `tools/`, `data/`, `strata_control` from 0.2.1 | `serve/server.py` of 0.2.1 imports `strata_control` (`engine_component`, `hipblaslt_tuning`, `vision_reader`); without it the server refuses to start |

The engine is a **portable build** (`STRATA_PORTABLE=ON`, one AVX2 baseline): `check_isa_guard` 0 violations,
0 `vpdpbusd` in `ggml_vec_dot_q8_0_q8_0`, and the `qemu-x86_64 -cpu Haswell` probe runs with no SIGILL and a
result identical to native. Note: 0.2.1's own guard list was missing the new trellis CPU kernel
`tq_rows_avx512`; we added it (the kernel sits behind `tq_isa()` → `cpu_avx512_ok()`), which is a local patch
to `tools/check_isa_guard.py`.

## What it is worth

Qwen3.8-Flash-Next-Uncensored **IQ2_XXS** pack, kv int8, `--mmap-experts`, ctx 65536, MTP spec 3, MI50,
HTTP `/v1/chat/completions`, 3 rounds, medians; prompt speed from the engine's own accounting:

| power | variant | prompt tok/s | decode tok/s |
|---|---|---|---|
| 80 W | clean 0.1.46 | 246–253 | 28.4–29.7 |
| 80 W | + `STRATA_HIP_PROMPT_F16=1` | 275–276 (+9…13 %) | unchanged |
| 80 W | + FP16 + rocBLAS table | **308–310 (+22…26 %)** | unchanged |
| 225 W | 0.1.46 vs 0.1.45 | identical (≤1 %) | noise |

TTFT at 225 W is about 45 ms lower on 0.1.46 than on 0.1.45 at every prompt size. The new 0.2.1 defaults
for packed models (I/O prefetch + decode gate) change **nothing** here: 0.1.45 already had that path on, and
the page cache holds ~99 % of the reads, so there is nothing to prefetch.

`qwen35moe` path — Qwen3.6-35B-A3B-UD-Q6_K, `--layer-split auto`, two cards, ctx 65536:
prefill **951 tok/s** at 4K (TTFT 4.31 s) and **791** at 16K (TTFT 20.72 s), decode **64.4 / 43.1**. That is
a different prompt path (its own q36 kernels, not MMQ), which is why the prefill is high despite the 27 GB
Q6_K file.

Verified on the card: Qwen3.6-35B-A3B-UD-Q6_K and Ornith-1.5-35B-A3B-Q4_K_M both start. Ornith also runs on
a single Radeon VII 16 GB — 15.9 GB of 16 GB used, tight.

## What is not proven

- **The table's rows are not bit-identical** to the default path: `STRATA_HIP_PROMPT_F16=1` rounds each
  16-bit GEMM's output to FP16. No identity gate (KL/bitwise) has been run, so the +22…26 % is not yet
  proven free.
- The table covers the dense prompt GEMMs only; **decode cannot move** from it (experts go through MMQ).
- The gate's GPU point ("real pack loading") was checked by hand, not by the automated gate run.
- Power-limit rows: the benchmark book records the cap in `mark`; speeds at a different cap are not
  comparable.
